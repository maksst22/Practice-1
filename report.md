# Отчёт по первой практике

## Тема: Разработка консольного приложения «Арена» на языке Java

---

## 1. Введение

**Цель практики:** закрепление навыков объектно-ориентированного программирования на языке Java, работа с коллекциями, файловым вводом-выводом, обработкой исключений и проектированием архитектуры приложения.

**Задачи:**

1. Спроектировать классы предметной области (герой, монстр, предмет, результат боя).
2. Реализовать консольный интерфейс с меню.
3. Реализовать боевую систему с проверкой допуска.
4. Реализовать сохранение и загрузку состояния сеанса.
5. Реализовать загрузку каталогов товаров и монстров из внешних файлов с валидацией.
6. Оформить проект и подготовить документацию.

---

## 2. Постановка задачи

Разработать консольное приложение «Арена», в котором пользователь управляет героем и сражается с монстрами. Приложение должно поддерживать:

- создание героя с выбором имени и класса (воин, маг, лучник);
- просмотр информации о герое и его инвентаря;
- лавку с возможностью покупки и продажи предметов;
- просмотр полного и доступного списка противников;
- поиск противника по имени и сортировку по уровню;
- проведение одиночного боя и серии боёв;
- ведение летописи боёв со статистикой;
- сохранение и загрузку сеанса;
- загрузку каталогов товаров и монстров из внешних файлов.

---

## 3. Архитектура приложения

Проект состоит из семи классов:

| Класс | Назначение |
|---|---|
| `Arena` | Главный класс, меню, вся логика взаимодействия с пользователем, сохранение и загрузка |
| `Hero` | Модель героя: имя, класс, уровень, опыт, здоровье, золото, инвентарь |
| `Monster` | Модель монстра: имя, уровень, атака, здоровье, обязательный предмет, награды |
| `Item` | Модель предмета: имя, тип, сила, цена, эффект расходника |
| `Battle` | Логика боя: расчёт урона и проведение боя |
| `BattleResult` | Результат одного боя (иммутабельный) |
| `Guard` | Проверка допуска героя к монстру |

**Схема взаимодействия:**

```
Arena ──> Hero ──> Item
  │
  ├──> Monster
  ├──> Battle ──> BattleResult
  ├──> Guard
  └──> history: List<BattleResult>
```

**Применённые принципы ООП:**

- инкапсуляция — поля `private final`, доступ через геттеры;
- иммутабельность — классы `Item`, `Monster`, `BattleResult` неизменяемы;
- разделение ответственности — бой, допуск и UI вынесены в отдельные классы;
- обработка исключений — `IllegalArgumentException`, `IOException`.

## 4. Ключевые фрагменты реализации

### 4.1. Расчёт силы героя

```java
public int getPower() {
    int power = level * 10;
    for (Item item : inventory) {
        power += item.getPower();
    }
    return power;
}
```

Сила героя складывается из уровня и суммы силы всех предметов в инвентаре.

### 4.2. Расчёт урона в бою

```java
public int predictDamage(Hero hero, Monster monster) {
    int heroPower = hero.getPower();
    int monsterPower = monster.getLevel() * 10 + monster.getAttack();
    int difference = heroPower - monsterPower;

    if (difference > 30) return 0;
    if (difference >= 1) return Math.max(10, monster.getHealth() / 4);
    return Math.max(40, monster.getHealth() / 2);
}
```

Чем больше разница в силах, тем меньше урона получает герой.

### 4.3. Проверка допуска к бою

```java
public String check(Hero hero, Monster monster, int predictedDamage) {
    if (hero.getHealth() <= 0) return "Герой мёртв";
    if (hero.getLevel() < monster.getLevel()) return "Уровень героя недостаточен";

    String requiredItem = monster.getRequiredItem();
    if (requiredItem != null && !hero.hasItem(requiredItem)) {
        return "Нет обязательного предмета: " + requiredItem;
    }

    if (hero.getHealth() <= predictedDamage) {
        return "Герой не переживёт ожидаемый урон";
    }
    return null;
}
```

Метод возвращает `null`, если бой разрешён, либо строку с причиной отказа.

### 4.4. Сохранение сеанса

```java
properties.setProperty("hero.name", hero.getName());
properties.setProperty("hero.level", String.valueOf(hero.getLevel()));
// ... сохранение инвентаря и летописи ...

try (var writer = Files.newBufferedWriter(
        Path.of(SESSION_FILE),
        StandardCharsets.UTF_8,
        StandardOpenOption.CREATE,
        StandardOpenOption.TRUNCATE_EXISTING)) {
    properties.store(writer, "Arena session");
}
```

Состояние сохраняется в `arena-session.properties`.

### 4.5. Загрузка каталогов с валидацией

```java
private void validateMonsterRequirements(List<Monster> monsters, List<Item> shop) {
    for (Monster monster : monsters) {
        String required = monster.getRequiredItem();
        if (required == null) continue;

        boolean found = false;
        for (Item item : shop) {
            if (item.getName().equalsIgnoreCase(required)) {
                found = true;
                break;
            }
        }

        if (!found) {
            throw new IllegalArgumentException(
                "Для монстра \"" + monster.getName() +
                "\" отсутствует обязательный предмет \"" + required + "\"");
        }
    }
}
```

Проверяется, что для каждого монстра, требующего предмет, этот предмет есть в лавке. Если нет — загрузка отменяется, текущие каталоги не изменяются.
